Die eigene Cloud – dezentral, quelloffen, mandantenfähig.

cloud-project macht aus beliebiger Hardware – Raspberry Pi, Notebook, Mini-PC oder Rack-Server – eine Cloud mit den Grunddiensten eines Hyperscalers. Vom Homelab mit zwei Knoten bis zum Rechenzentrum mit tausenden Knoten, ohne zentralen Controller.

Kabel rein → Knoten erscheint → freigeben → Rolle zuweisen → fertig.

Funktionsumfang Architektur Dokumentation
  • 2 – 10.000+Knoten je Installation, in Zellen und Regionen
  • 3 ZugängeAPI, Web-Portal und MCP mit gleichem Funktionsumfang
  • ARM64 + x86_64gemischt ab dem ersten Tag
  • RustKern, Agent und Dienste; AGPL-3.0-or-later

Worum es geht#

Öffentliche Clouds bieten Komfort: Maschinen, Speicher und Netze per Klick oder API. Wer Daten, Kosten und Abhängigkeiten selbst in der Hand behalten will, muss diesen Komfort heute aus vielen Einzelprodukten zusammenbauen und pflegen. cloud-project verfolgt einen anderen Weg: Eine einheitliche Plattform übernimmt Hardware per Netzwerk- oder USB-Boot, verwaltet sie als Pool und stellt darauf Dienste bereit, die sich wie die eines Hyperscalers anfühlen – virtuelle Maschinen, Container, Managed Kubernetes, Block- und Objektspeicher, virtuelle Netze, Identitäten, DNS und KI-Inferenz.

Die Plattform läuft auf der Hardware, die sie steuert. Jeder Knoten trägt denselben Agenten; Portal, API und MCP-Server sind auf jedem Knoten erreichbar. Fällt ein Knoten aus, übernimmt ein anderer.

Leitprinzipien#

  • DezentralKein zentraler Controller. Zustand über Raft je Zelle, Mitgliedschaft über Gossip. Ausfall der Steuerung stoppt keine laufenden Workloads.
  • API-first, drei gleichwertige ZugängeJede Funktion auf jeder Ebene über API, Portal und MCP – auch Ersteinrichtung und Adoption. Die Gleichwertigkeit wird in der CI geprüft.
  • Zero-Touch nach dem KabelKein Bildschirm, keine Tastatur, kein SSH. Einzige bewusste Handlung ist die Freigabe (Adoption) eines neuen Knotens.
  • Skaliert in beide RichtungenZwei Knoten sind ein vollwertiger Betriebsmodus. Wachstum auf tausende Knoten über Zellen und Regionen ohne Neuinstallation.
  • Unveränderliche KnotenEigenes Image-OS cpOS mit dm-verity, A/B-Updates, Secure Boot und TPM-gebundener Verschlüsselung.
  • Secure & Compliant by DesignmTLS überall, Mandantentrennung auf allen Schichten, lückenloses Audit, Nachweise für ISO 27001 und BSI IT-Grundschutz.
  • Open Source durchgehendNur quelloffene Abhängigkeiten, eigene Komponenten in Rust, signierte Releases mit SBOM.
  • Bewährtes integrierenKein eigener Hypervisor, kein Dateisystem von Null: Die Plattform baut Steuerung, Automatisierung und die einheitliche Oberfläche.

Der erste Schwerpunkt ist das Homelab – die Architektur enthält aber keine Entscheidung, die das Rechenzentrum verbaut.

So sieht das aus#

Ein neuer Knoten bootet per Netzwerk, meldet seine Hardware und wartet in der Quarantäne auf Freigabe. Das geht im Portal, per API oder über einen KI-Assistenten via MCP – mit identischem Ergebnis:

sh$ cpctl list discoveries
NAME        ARCH     CPU  RAM    DISKS        TRUST  CODE
d-7f3a91    arm64    4    8 GiB  1× 256 GB    T1     482-913
$ cpctl discovery adopt d-7f3a91 --node-name node-03 --dry-run
$ cpctl discovery adopt d-7f3a91 --node-name node-03 --confirmation-token <token> --wait
$ cpctl list nodes
NAME     ROLES                    STATE           VERSION
node-01  control,boot             Aktiv           0.4.0
node-02  control,compute-vm       Aktiv           0.4.0
node-03  -                        Bereitgestellt  0.4.0

(Ausgabe beispielhaft; Befehle und Felder können sich bis zum ersten Release ändern.)

Projektstand#

Die Architektur ist abgenommen (Meilenstein „Architektur steht“, November 2026). Die Phase „Fundament“ läuft: Agent, Steuerungsebene, OS-Image, Boot und Adoption, Release- und Update-Kette sowie Plattform-DNS entstehen. Mehr unter Status & Roadmap.

Das Projekt ist noch nicht für den Produktiveinsatz bereit. Der Quellcode wird veröffentlicht, sobald Lizenzdateien, Sicherheitsrichtlinie und REUSE-Konformität vollständig stehen.

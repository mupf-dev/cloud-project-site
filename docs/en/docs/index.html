Docs

Public editions of BYOC's concepts, architecture decision records (ADRs) and processes, condensed from the project documents for a general audience.

Concepts and architecture decisions 21 Pages

  • Vision, Terminology and ScopeTarget picture, guiding principles, target audiences, glossary, node lifecycle, roles, scaling tiers and scope of BYOC (Build Your Own Cloud).
  • Rust Stack and Core LibrariesArchitecture decision on the agent's Rust libraries – runtime, APIs, consensus, gossip, TLS, persistence, testing, supply chain, toolchain and licenses.
  • API-first – API, Portal and MCP as EqualsWhy every function is first an API operation, how resources and operations are structured, and how the portal and MCP are derived from them and checked for parity.
  • Control Plane ArchitectureAgent, gossip membership (SWIM), Raft consensus per cell, two-node operation with witness, cells and regions, reconcilers, bootstrap and failure behavior.
  • Boot and AdoptionHow nodes join the platform – the first node via USB stick, further nodes via network boot, a boot service without a single point of failure, discovery quarantine, secured adoption, plus rejection, decommissioning and replacement.
  • NetworkNetwork zones, the encrypted WireGuard underlay, the in-house tenant overlay cp-vnet, workload attachment and north-south traffic with floating IPs, gateways and platform DNS.
  • Platform DNSThe DNS role cp-dnsd – authoritative zones of the cluster, DNSSEC, floating service addresses (VIPs) with Raft leases, and integration with the operator's DNS.
  • Tenants, Identity and AccessHierarchy of platform, tenant and project, identity types, sign-in with passkeys and OIDC federation, a hybrid authorization model combining a relationship graph and Cedar, tenant isolation, quotas, lifecycle and recertification.
  • OS Image (cpOS)The immutable node operating system – a Debian base built with mkosi, erofs and dm-verity, Unified Kernel Images, Secure and Measured Boot per platform, TPM-bound encryption, A/B updates with a health gate, plus hardening and SBOM.
  • Rollout ControllerHow platform updates reach the nodes in a rolling, quorum-safe way – release plans, ordering and gates, the health gate on the node, pausing and rollback.
  • StorageBlock, object and file storage from two nodes to thousands – the in-house block storage cp-blk with metadata in the cell Raft, tenant encryption on the compute node and a maturity gate before replication.
  • Security ModelWhom the platform trusts, for what, how that trust is proven and what happens when trust is lost – from trust anchors through node trust levels and remote attestation to break-glass and compromise.
  • CryptographyPrinciples of the cryptography concept – alignment with BSI TR-02102, two crypto profiles, a PKI with short lifetimes, two-layer encryption of data at rest and a roadmap to post-quantum cryptography.
  • Threat modelMethod and principles of the product risk analysis – STRIDE per trust boundary, assessment and treatment according to BSI Standard 200-3, abstract attacker models, security assumptions and maintenance of the model.
  • Portal technologyArchitecture decision for the web portal – why a Svelte 5 SPA embedded in the agent won out over Rust/WASM, React and server-side rendering.
  • AI-native platformHow BYOC manages models, operates inference endpoints, schedules accelerators and delivers AI services through its own AI gateway in a tenant-safe and compliant way.
  • Hyperscaler feature analysisWhich service categories from AWS, Azure and Google Cloud BYOC covers, how they are implemented (in-house development or external component) and in which phase.
  • License and governanceWhy the BYOC core is licensed under AGPL-3.0-or-later, which licenses apply to SDKs and documentation, how contributions work via DCO, and where the project stands under the Cyber Resilience Act.
  • Compliance requirementsWhich regulatory frameworks apply to BYOC, how the requirements catalog is structured, how obligations are split between platform, operator and tenant, and which precedence rules apply in case of conflicts.
  • BSI IT-Grundschutz modelingHow BYOC models the "platform" sub-domain of the information domain from the manufacturer's perspective according to Grundschutz++, maps requirements to components and evidence, and provides operators with a protection requirements template.
  • Compliance by DesignBYOC's 36 verifiable architecture guidelines, the CI checks and review checklist that go with them, and the "Security & Compliance" template that every architecture decision must contain.

Processes 4 Pages

  • Release signingTwo signing paths for releases, the format of the update metadata following the TUF approach, the processes and the reproducibility of builds.
  • Vulnerability managementHow BYOC receives, assesses, fixes and publishes security reports – including deadlines, CRA reporting obligations, VEX and SBOM.
